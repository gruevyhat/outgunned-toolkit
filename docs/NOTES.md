# Implementation Notes

## Scope

Milestones M0–M4 of `PLAN.md` are implemented. The M5 content-pack selector is now implemented for the standard character-building contracts; the other M5+ items remain deferred.

## Content packs and working sheets (2026-09-05)

- The menu can independently add Outgunned Adventure, Outgunned Superheroes, and a combined Action Flicks 1–3 / World of Killers supplement pack to Random, Guided, Questionnaire, and Crew creation pools. Every imported id is namespaced, source metadata stays on each record, and enabling a share link automatically enables its required pack.
- Standard-compatible imported content comprises 48 Roles, 117 Tropes, 261 Feats, 152 gear entries, and 17 Superpowers before adding the core catalogs. Project Medusa contains pregenerated characters but no additional character-creation options.
- Alternate creation formats (Fortune Seeker, Marvel, Prodigy, Master of the Multiverse, N.P.C., Power Guardian, The One, and Assassin) are retained in the source catalogs but are not offered by the standard Role + Trope builder because they replace its allocation contract. Supplement-specific paired Tropes without their own Feat list are likewise retained but not exposed as standalone core-style Tropes; no missing rule values were invented.
- Superheroes select their legal Role Attribute and receive a Power tracker in place of Adrenaline. Supplement gear grammars for weapons, precious items, and Cash-budget bundles are resolved by the shared engine.
- The on-screen Hero Sheet is now usable during play: Grit, genre resource, Spotlight, Cash, Lethal Bullets, Conditions, Mags, gear bag marks, Ride shields, mission, experiences, and storage are live controls. These values flow into copy links and PDF export. Per-field rerolls appear only after entering Edit Hero mode.
- Checked states use dark red with white text and fixed-size check marks. Checked and unchecked controls share the same grid geometry, including mobile layouts. The sheet navigation action is now Home.

## Data verification

- Source PDFs are read only from the gitignored `books/` symlink.
- Values that cannot be confirmed must use `status: pending`; no rules value is inferred.
- Questionnaire prompts and general name lists are original content as specified by the plan.

Gate M0 spot checks were made against the local PDFs using layout-preserving extraction: Commando (p. 20), Agent (p. 26), and Spy (p. 38); Bad to the Bone (p. 42), Last Boy Scout / Girl Scout (p. 45), and Vigilante (p. 47); the p. 48 Feat index plus individual entries for Gunslinger, Cash Flow, Hard to Kill, Selfless, and Too Young to Die; Villain Generator (Assistant Director p. 13), Help/Flaw (p. 17), and Thematic Oracles (p. 56). The three tropes affected by markdown heading loss were checked against the PDF.

## Plan decisions

- The plan lists 16 Skills in prose but names 20 Skills in its canonical sheet-order list and field map. The engine uses all 20 canonical ids.
- The plan's feat integrity line says “47 core + Too Young to Die,” but Corebook p. 48 says there are 47 total and includes Too Young to Die in that list. The shipped catalog therefore has 47 verified entries, not a fabricated 48th.
- Hero share decoding validates against current rules data before rendering.
- Generated metadata uses a stable epoch timestamp in pure engine paths so seeded output stays reproducible.

## Gate verification

- Automated: 1,000 seeded heroes validate; 50 seeded PDFs and the Johnny Reed fixture render as one-page landscape Letter documents; 200 campaigns generate; questionnaire diversity exceeds the plan threshold; all seven screens render.
- Browser run-through: Random Hero and a complete seven-step Guided Hero were exercised without console errors. At a 390 × 844 viewport, both the menu and hero sheet stayed within a 390 px document width with no horizontal page overflow.
- PDF layout received a 100-hero maximal-style render check during implementation. The Johnny Reed export contains all planned sheet regions. Browser download was not used during automated QA because engine-level PDF loading verifies the generated bytes directly.
- The single-file build contains no external script or stylesheet tags. Direct `file://` navigation is blocked by the automation browser's URL policy, so offline correctness is established by the single-file bundler output and absence of external assets.
